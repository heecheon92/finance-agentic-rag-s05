# 에이전트 정책

이 문서는 금융 문서 질의응답 에이전트의 재검색, 미답변,
상담 안내 및 고지 정책과 그 선택 근거를 기록한다.
실행 설정은 `src/finrag/agent/policy.yaml`과 환경변수를 기준으로 한다.

정책 버전: `2026-09-08.1` | 작성: 2026-10-09 | 적용: S05 학습·평가 환경

## 1. 재검색 상한

| 항목            | 선택                                   | 근거                                                                                            |
| --------------- | -------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `max_retries`   | 2                                      | 동일한 10문항 비교에서 상한 0보다 답변률이 높고 오거절률이 낮아, 추가 지연을 감수하고 유지한다. |
| 상한에 닿으면   | `insufficient`는 근거 한계를 밝힌 답변 | 관련 근거가 일부 있으므로 확인된 부분만 안내한다.                                               |
| 근거 없음       | `none`은 횟수와 관계없이 즉시 거절     | 근거가 없거나 무관하다고 판정된 경우 답변을 생성하지 않는다.                                    |
| 재검색 1회 비용 | 별도 측정하지 않음                     | 저장된 지연·토큰 사용량은 문항 전체 값이므로 재검색 1회분을 분리할 수 없다.                     |

동일한 10문항에서 상한 0 → 2로 변경했을 때,
답변률은 70% → 90%, 오거절률은 30% → 10%,
평균 지연은 8,034.1ms → 12,696.2ms였다.
MRR은 두 실행 모두 0.675로 같았다.

출처: `results/agentic_sample_retry0.json`,
`results/agentic_sample_retry2.json`의 `overall`.

이는 단일 비교 실행에서 관찰한 결과다. LLM 응답 변동이 포함되므로
차이를 재검색 상한만의 효과로 단정하지 않는다.
답변률 상승도 답변의 정확성 향상을 직접 증명하지는 않는다.
상한 1·3은 아직 비교하지 않았다.

## 2. 지연 예산

현재는 학습·평가 환경으로, 서비스 지연 목표는 아직 정하지 않았다.
아래 값은 보장하는 예산이 아니라 동일한 40문항의 실행 관측값이다.

| 구간                                    | 예산 | 실측                                               |
| --------------------------------------- | ---- | -------------------------------------------------- |
| Hybrid 검색 전체(Dense+BM25+RRF+리랭킹) | 미정 | 평균 1,502.7ms, p95 1,191.6ms                      |
| 검색과 리랭킹 각각                      | 미정 | 위 결과에서 단계별 시간은 분리하지 않음            |
| 에이전트 추가 처리                      | 미정 | 전체 평균 차이 약 9,999.8ms. 개별 단계 시간은 아님 |
| Agentic 전체                            | 미정 | 평균 11,502.5ms, p95 21,159.0ms                    |

출처: `results/hybrid.json`, `results/agentic.json`의 `overall`.

평균 차이는 재작성·필터 추출·판정·답변 생성·재검색 등을 포함한
추가 처리의 대략적인 규모이며, LLM 답변 생성만의 비용으로 해석하지 않는다.
서로 다른 실행의 모델 로딩·캐시·응답 변동도 포함될 수 있다.
두 실행의 p95 차이 역시 특정 단계의 p95를 뜻하지 않는다.

향후 정한 지연 목표를 초과하면 재검색 상한 축소를 우선 검토한다.
10문항 비교에서 상한 2 → 0은 평균 지연을 약 4.66초 줄였지만,
오거절률이 10% → 30%로 높아졌다. 따라서 무조건 축소하지 않고
품질 손실의 허용 범위를 정한 뒤 재평가한다.

## 3. 미답변 문구

현재 `src/finrag/agent/policy.yaml`의 문구를 유지한다.
학습·평가용 문구이며, 실제 고객 서비스에 사용하기 전 법무·CS 검토가 필요하다.
아래는 정책에 정의된 문구 목록이며, 모든 상황의 자동 탐지·출력을 보장한다는 뜻은 아니다.

| 상황                   | 문구                                                                                               | 검토 상태      |
| ---------------------- | -------------------------------------------------------------------------------------------------- | -------------- |
| 근거 없음              | 문서에서 근거를 찾지 못했습니다. 질문을 조금 더 구체적으로 알려주시거나 상담 창구로 문의해 주세요. | 법무·CS 미검토 |
| 근거 부족              | 관련 조항은 찾았지만 질문에 답하기에는 근거가 부족합니다. 확인된 내용만 안내드립니다.              | 법무·CS 미검토 |
| 문서 밖(산출방법서 등) | 이 값은 약관·설명서에 없고 산출방법서 등 비공개 문서에 있습니다. 해당 금융회사 확인이 필요합니다.  | 법무·CS 미검토 |
| 문서에 계산 값이 없음  | 문서의 해당 항목이 비어 있어({field}) 계산할 수 없습니다. 개별 계약서 또는 창구 확인이 필요합니다. | 법무·CS 미검토 |
| 질문에 계산 값이 없음  | 질문에 값이 없어({field}) 계산하지 않았습니다. 금액과 기간을 알려주시면 계산해 드립니다.           | 법무·CS 미검토 |
| 개인정보 요구          | 개인의 계좌·잔액 등 개인 금융정보는 이 시스템에서 다루지 않습니다.                                 | 법무·CS 미검토 |
| 실행 요구              | 이 시스템은 조회·안내만 제공하며 거래를 실행할 수 없습니다.                                        | 법무·CS 미검토 |

`{field}`는 실행 시 누락된 항목명으로 대체하는 자리다.
“문서 밖” 문구는 해당 값이 비공개 산출방법서 등에 있다는 근거가 있을 때만
사용해야 하며, 단순 검색 실패를 비공개 문서의 존재로 단정해서는 안 된다.

## 4. 에스컬레이션

질문에 아래 키워드가 포함되면 다음 안내를 추가한다.

> 정확한 안내를 위해 담당 상담사 연결이 필요한 내용입니다.

| 트리거      | 자동 응답만으로 끝내지 않는 이유                           |
| ----------- | ---------------------------------------------------------- |
| 민원        | 개별 불만의 사실관계 확인과 정식 접수·처리가 필요하다.     |
| 분쟁        | 당사자 간 주장과 계약 내용을 함께 검토해야 한다.           |
| 소송        | 법적 판단과 대응은 문서 검색 답변만으로 확정할 수 없다.    |
| 손해배상    | 책임 여부와 손해액은 개별 증빙·법률 검토가 필요하다.       |
| 해지환급금  | 개별 계약·납입 이력·산출 기준에 따른 금액 확인이 필요하다. |
| 보험금 청구 | 보장 조건뿐 아니라 사고 내용과 청구 서류를 확인해야 한다.  |
| 불완전판매  | 설명 의무 이행 여부와 판매 과정의 증빙을 검토해야 한다.    |

안내 대상은 해당 금융회사의 담당 상담 창구다.
실제 연결 채널과 응답 시간 목표는 아직 정하지 않았다.

현재 구현은 `nodes._escalation()`의 키워드 포함 여부 검사이며,
`answer`와 `abstain`이 상태의 `escalation_reason`에 안내 문구를 담는다.
상담사 자동 연결·접수 기능은 없고, 키워드가 없는 유사 표현을
의미적으로 탐지하는 기능도 없다.

## 5. 고지

체크는 정책 문구의 존재가 아니라 해당 동작의 구현 확인을 뜻한다.
코드에서 확인한 조건과 아직 충족하지 못한 범위를 함께 기록한다.

- [ ] AI 생성 고지를 모든 응답에 붙인다.
      `nodes.answer()`는 AI 생성 안내를 `notices`에 추가하지만,
      `nodes.abstain()`은 기존 고지만 전달하므로 거절 응답까지 일괄 적용되지는 않는다.
- [x] 심의필 만료 표시가 있는 근거에 경고를 붙인다.
      `nodes.retrieve()`가 근거의 `expired` 표시를 확인하여 만료 안내를 추가한다.
- [x] 열화 재현본 표시가 있는 근거에 고지를 붙인다.
      `nodes.retrieve()`가 `synthetic_degraded` 표시를 확인하여 안내를 추가한다.
- [ ] 세율·한도 등 법령 상수 사용을 빠짐없이 고지한다.
      일부 계산 함수는 `constants.disclaimer()`를 경고에 넣고,
      `calc_node`는 이를 `notices`로 전달한다. 다만 모든 상수 사용 경로에
      공통으로 적용되는 구조는 아니므로 전체 적용을 보장하지 않는다.
- [ ] 범위만 공시된 값을 단일 수치로 단정하지 않는다.
      `policy.yaml`에 `range_only` 문구는 있지만, 확인한 답변·계산 노드에
      이를 자동 적용하는 처리는 없다. 적대적 평가 A03(확신 유도)도 실패했다.

고지는 응답 상태의 `notices`에 담기며, `scripts/ask.py`가 이를 출력한다.
별도 UI를 붙일 때도 이 필드를 사용자에게 표시해야 한다.
현재 적대적 평가 결과는 5문항 중 4문항 통과이며, 위 미충족 항목을
해결한 것으로 간주하지 않는다.
